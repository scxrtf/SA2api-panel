== 1. 需求 ==
请求报错时，把「报错内容」落进项目日志——原先 RequestLog 只有 status + errKind，
排障只能看到 401 / model_blocked 这类分类码，看不到上游到底说了什么；
运行日志的 chat ERR 行同样只有状态与耗时。

== 4. 边界与取舍 ==
- 只记错误路径：成功请求 errMsg 留空，避免表体积随正常流量增长。
- 单行 + 1000 字符上限：网关 HTML 常达数 KB，原样落库既占空间又破坏 grep；
  完整定位仍在运行日志/上游复现，日志只留可读摘要。
- 不记录请求体（prompt）：属用户内容，本次仅采「上游报错正文」，与既有 privacy 边界一致。
- UsageEvent 未加该字段：用量台账关注 token/积分，排障走请求日志；如需图表侧联动可另开。
