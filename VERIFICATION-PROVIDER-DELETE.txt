VERIFICATION - 供应商删除：超级密码 + 联动清理密钥授权
日期: 2026-10-23 (Asia/Shanghai)

问题（两条）:
  P1 供应商删除无任何二次确认，与密钥授权（PATCH /keys/{name}）权限口径不一致。
  P2 供应商删除后，ApiKey.providers 白名单里仍残留该供应商名；
     重新保存授权时 PATCH 校验「未知供应商」直接 400，无法改写。

修复:
  MODIFIED: src/app/api/panel/providers/[name]/route.ts
    - DELETE 必须携带超级密码（body.super_password 或 ?super_password=，
      复用 panel-auth.verifySuperPassword，SHA-256 + timingSafeEqual）。
    - $transaction 内先扫 providers contains 该名的 ApiKey，按逗号精确剔除该名
      （"*" 保持不变），再删 Provider；返回 { scrubbed_keys }。
  MODIFIED: src/app/panel/views/gateway.tsx
    - ProvidersBox.remove 改为 window.prompt 收超级密码，随 DELETE body 提交；
      空密码前端直接报错不发请求。

验证记录:
  [1] npx tsc --noEmit -p tsconfig.json  -> exit 0
  [2] npx eslint src/app/api/panel/providers/[name]/route.ts src/app/panel/views/gateway.tsx
      -> exit 0
  [3] npx next build -> exit 0

行为断言（未连库，编译期验证）:
  - 无密码/错密码 DELETE -> 403 超级密码错误
  - 正确密码 + 存在供应商 -> 200，同事务清理关联 key 授权，返回 scrubbed_keys
  - 正确密码 + 不存在供应商 -> 404
  - "*" 授权 key 不受影响；仅含被删供应商的 key 授权串清空（=未绑定不限制）
