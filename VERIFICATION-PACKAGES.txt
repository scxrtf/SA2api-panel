== 1. 报障 ==
积分构成页 190****5127（uid 6b55a84f-40c6-4b01-952d-5caf2247774f）显示「剩余 0 / 总量 0」，
错误正文是网关 HTML：<html>…401 Authorization Required…openresty…Powered by APISIX…

== 2. 现场复现（真实上游，2026-10-23 16:0x）==
样本 6b55a84f：
  POST https://www.codebuddy.cn/v2/billing/meter/get-user-resource  → 401 text/html (APISIX HTML)
  GET  https://www.codebuddy.cn/console/account                     → 401 text/html (同上)
  GET  https://www.workbuddy.cn/console/account                     → 401 text/html (同上)
  POST https://copilot.tencent.com/v2/plugin/auth/token/refresh      → 401 {"code":12153,"msg":"12153:refresh token is invalid"}

全量 28 号扫描同一端点：4 成功 / 24 失败，失败均为 HTML 401，刷新一律 12153。

JWT 解码（不验签）：失败号 accessToken 的 iat 均为 2026-10-22T14:00Z（保活批次写入），
exp 在 2026-11-19，即「DB 认为还有 27 天有效、上游已整体吊销」——不是 access token 自然过期，
而是会话（access+refresh）被上游同时作废，唯一恢复路径是重新登录。

== 3. 根因 ==
A. 账号层：24 个号的上游会话已吊销（refresh token 亦失效），代码无法从死 token 推出积分。
   「0/0」不是可修的数据，只是不该被当作真实余额展示。
B. 面板层（代码缺陷，本次修复）：
   1) /api/panel/packages 直接拿 DB 的 accessToken 快照调上游，从不刷新 → 快照一落后必然 401；
   2) 失败后 remain/size 留在 0，前端原样展示「剩余 0 / 总量 0」，并把 HTML 401 原文塞进 .msg.err；
   3) CN/国际域合计把失败号的 0 累加进去，整页读出「CN 累计余额」偏低的错误结论。

== 4. 改动 ==
新增 src/lib/accountSession.ts（会话自愈层）
  - withFreshAuth()：取数前按 refresh_skew_sec 预刷新；遇 401 刷新后再重试一次（一次为限）
  - refreshShared()：同 uid 刷新单飞（single-flight），避免并发重复消费 refresh token
  - latestShape()：重试前重读 DB 凭证（并发刷新后旧 RT 已作废）
  - sanitizeUpstreamMessage()：网关 HTML → 单行摘要（title 优先 + 按词去重 + 截断 200）
  - classifySessionError()：session_dead / auth_rejected / upstream_error 三个稳定原因码
  - SESSION_DEAD_TTL_MS=5min 负缓存：死号在 TTL 内不再打上游
    （24 死号 × 60s 轮询 = 每分钟 24 次无效刷新的浪费归零）

src/app/api/panel/packages/route.ts
  - 取数改走 withFreshAuth
  - 行新增 ok / reason；失败行 remain/size 仍为 0 但 ok=false（供前端区分「取不到」与「真的 0」）
  - error 统一过 sanitizeUpstreamMessage；无 token 行也带 reason
  - 响应新增 failed / total；排序：成功行按余额降序在前，失败行沉底但不隐藏

src/app/panel/views/packages.tsx
  - 失败行：标签「会话失效 / 鉴权被拒 / 上游失败」+ 一句结论 + dim 的上游原文，不再显示 0/0
  - 域合计只累加成功行，新增 warn 标签「N 个账号取数失败 · 未计入合计」
  - 账号头部昵称与 uid 之间加「·」分隔（原先昵称+uid+CN 标签连读成
    「190****51276b55a84f-…CN」，易被误读为一个字段）
